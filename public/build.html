Architecture · what we built

One engine. Three surfaces. A graph that survives between queries.

Pulse is a public-signal intelligence engine. The deployed web app, the public MCP, and the JSON API are all views over the same source-linked knowledge graph. The agents propose; the deterministic Applier writes; every claim has the verbatim evidence behind it.

The engine

Capture → extract → crew → Applier → graph.

Every claim on the graph is linked back to the verbatim text it came from, the source that produced it, and the timestamp that source carried when it was ingested. No claim exists without evidence. The agents propose; the Applier applies.

  • Capture Continuous radio capture against ten Barbadian FM stations (VOB 92.9, CBC 94.7, LIFE 97.5, HOTT 95.3, 98.1 The One, Q 100.7, Slam 101.1, Y103.3, The Beat 104.1, Radio Bimshire 106.1) via ffmpeg timestamped atoms, with parallel text/web/RSS, TikTok, Instagram, YouTube, and corpus adapters running the same shared pipeline.
  • Transcription & extraction Three production audio passes per chunk: fast local transcription for triage, NVIDIA Nemotron Speech Streaming for the canonical transcript, and a stage-2 model (MiniMax M3) for typed extraction with HIGHRISE as the bounded fallback. A MiniMax spend tracker enforces the budget. On the social-video path, BimOmni (a Qwen3-Omni LoRA fine-tuned on the Barbados newspaper archive) replaces Nemotron to recover proper nouns ("Kidscape Barbados" not "Kids Cake").
  • Ingest crew Stage 2 emits a typed extraction. The Curator agent (CrewAI) resolves mentions and proposes a Changeset of ChangeOp values. The optional Reviewer agent approves or rejects each op. Tools gate unsafe operations and validate searched entity IDs. Every kickoff emits its full event stream — LLM calls, tool usage, task boundaries — through the CrewAI event bus into the persisted agent_trace_event table.
  • Deterministic Applier The Applier is the only code that mutates the graph, and it writes in one transaction. Invalid ops are rejected without abandoning the rest of the batch. Source-ledger writes are persisted before any graph mutation, so every claim has a durable handle back to the verbatim evidence and the agent run that proposed it.
  • Ask side — bounded agent retrieval The search side is one bounded agent loop (5 steps, 18K tokens, 18s wallclock) followed by one bounded composer call. The agent drives eleven typed tools: resolve_entities, search_text, search_claims, walk_graph, expand_entity, recent_claims, check_series, get_pulse, get_evidence, ask_user, final_answer. Tool calls dispatch in parallel within a turn; the watchdog stops runaway loops. p50 4.5s, p95 13.2s on the 33-query canonical suite.
  • Three read surfaces The deployed web app (app.pulsebarbados.com), the read-only MCP server (mcp.pulsebarbados.com), and the JSON API (/api/health, /api/feed, /api/ask) all read from the same graph. The chatbot sits on top of the evidence graph any third-party agent can read.

Public MCP · read-only
